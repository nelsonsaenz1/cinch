Stylist — four doors, owned garments only
Thirty-six 393×852pt frames for src/app/stylist.tsx, exported at 790×1708. The stylist answers from clothes already owned; it never invents a garment, a brand, a price or a place to buy one. State names on this desk are for inspection only and never appear in the app.

Implementation handoff
Route & ownershipsrc/app/stylist.tsx presented as a sheet route, not a tab. StylistHeader, StylistOpening (now four image-led doors), the on-device questionnaire, Composer, MessageBubble, inline OutfitStrip, loading / closet-too-small / closet-failed states all keep their files. No new screen and no new navigation entry.DoorsThe four doors map to existing intents in fixed order and launch the local questionnaire. No model call happens between taps. Each door is a real garment well with a label plate; the artwork here is representative, production binds to already-authorized owner images.Allowance displayA minimal display object — { promiseLimit: 5, successfulUsed, remaining } — is returned by a server-controlled response or RPC counting successful remote stylist replies across the current UTC month. On-device fact answers and failed or provider-denied turns never count. The mark renders only when remaining ≤ 2, only for confirmed Standard, and never while entitlement or usage is loading. The client never infers it from one session.Plan truthFree excludes Stylist. Standard is exactly five chats a month. Pro displays Unlimited; the 100/day anti-abuse ceiling is never shown. The 14-day trial is server-side and follows the verified entitlement — no client timer, no Apple introductory offer, no hardcoded price anywhere in this route.Model boundaryThe model never receives the raw closet. On-device logic assembles candidates from real owned garments; the server sees a bounded digest and shortlist. Any outfit or item ID in the reply that does not resolve to a current authorized item is dropped before render. A deleted or unavailable piece disappears silently rather than becoming ghost data.Local factsQuestions answerable by counting in-memory wardrobe facts are answered on device, are labelled as counted rather than generated, and never spend the allowance.ConsentAI consent is requested at the model boundary, not at launch. Declining leaves doors, facts and history fully usable. Consent state routes to the existing consent path and is never mislabelled as an outage or a paywall.Denials402 = plan_excluded: Stylist is part of Standard and Pro, routes to the existing vendor-owned upgrade placement, not retryable. 429 = allowance exhausted: server-owned period and reset timing, monthly for Standard and daily for Pro, no invented date if none is returned, not retryable. Transport and provider failures are a third class: retryable in place, no duplicate turn, no lost pending message, and no promise of background sync.HistoryRestoration resolves stored IDs back to current authorized items. Missing IDs are omitted with no gap, count, placeholder or accessibility hint. Nothing reveals that an item once existed.Wardrobe statesA failed wardrobe read renders the load-error state and never claims an empty or too-small closet. Not-enough-pieces appears only after a successful read returning too few items, and says plainly that suggestions come only from clothes actually owned.Analytics allowliststylist_opened, door_tapped(index 1–4), questionnaire_step(n), chat_sent, chat_reply_ok, chat_error(enum plan_excluded|quota|transport|consent), local_fact_answered, plates_shown(count), plate_tapped, allowance_mark_shown(bool). Forbidden in every payload: prompt or free text, transcript, response text, item or outfit IDs, garment names, image URLs or paths, prices, history content, friend data, user identity, and location.AccessibilityFocus order per screen: header → new chat → doors in visual order → allowance mark when present → composer field → send. In conversation: latest turn → inline plates as one labelled group each → follow-up chips → composer. Every door, chip, plate, field and send control is ≥44pt, ≥56pt at AX sizes. Dynamic Type reflows doors to a single stacked column inside a scroll region; type never shrinks and nothing clips. VoiceOver announces plates as owned garments, never as products.Motion & hapticsSelection haptic on door tap and answer selection; one notification haptic on a settled reply. No haptic on open, cancel, error or retry start. Reduce Motion drops the stagger, the settle and the plate cascade in favour of a cross-fade, leaving composition and state identical.TestsDoor order and count; questionnaire completes with zero network calls; consent gate fires at the model boundary only; fabricated outfit ID dropped; deleted garment omitted with no ghost data; allowance mark hidden above 2, hidden while loading, hidden for non-Standard, decremented only after a successful remote reply; 402 and 429 render distinct non-retryable states; transport error retries without duplicating; local fact answers spend nothing; history restoration omits revoked items; AX-XXXL renders all four doors reachable; short device keeps the composer above the home indicator; Reduce Motion preserves state; analytics payload audit rejects any forbidden field.Fingerprint / OTAPresentation is JS-only: no new package, native module, permission string, entitlement, vendor, data recipient, public surface or config plugin. The Expo fingerprint is unchanged, so this ships over the air on the existing binary once tests pass.DeviationsOne. The opening uses a two-column door grid rather than a single-column list, because four full-width rows push the composer below the fold on a 667pt screen. At AX-XXXL the grid becomes the single stacked column the directive describes.
