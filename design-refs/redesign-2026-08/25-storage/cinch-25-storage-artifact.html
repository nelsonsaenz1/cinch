Implementation handoff
Route & ownershipsrc/app/storage.tsx keeps its route as a pushed screen from Closet and Profile. Data and mutations reuse src/features/closet/storage.ts; ceilings and plan figures reuse src/features/billing/use-capacity.ts reading plans.ts. Changed: presentation only — Closet’s garment-card and grid language at lower emphasis, a three-part capacity line, and one primary action.What a stored piece isis_archived = true. It keeps its private photographs, wear history and price, and is excluded from the active closet, from outfit planning and styling, from friend closet reads, and from image serving. Nothing in this design implies deletion or continued styling — the empty state says so explicitly, and the success mark says the piece can be styled again only after it is back.Two ceilings, two meaningsActive counts unarchived pieces only. Total counts every piece, active plus stored. Free 10/30, Standard 150/450, Pro 1000/3000, all read from plans.ts. The capacity line uses one grammar: N stored · A of L active · T of TL total. The total limit is never called “stored pieces”, and active-full is never conflated with total-full. Any unknown part is omitted rather than printed as zero, a dash or an estimate.Restore rulesRestoring sets is_archived to false and does not change the total, so total-full alone never blocks it — that state says so outright, because a reader would otherwise assume the opposite. Active-full does block it: the database refuses, the action disarms, and the remedy offered is storing an active piece. Both-full resolves the same way, since freeing an active place is sufficient.Failure is not emptinessA read failure renders its own state naming that the pieces are safe on the server; it never falls through to the empty state. An empty mutation result is treated as failure, not success — the piece stays in the grid, the selection and scroll position are preserved, and the notice states that nothing changed. A row already changed on another device reconciles quietly and is not reported as an error.DEVIATION — permanent deletionBoth-full is genuinely resolvable by storing an active piece, so deletion is not required to escape it. It appears in the both-full recovery sheet only, as a quiet text-only line beneath the two constructive routes, and leads to a separate explicit destructive confirmation owned elsewhere. It is never a grid action, never a swipe, and never the filled control. Implementation note: if no destructive confirmation exists on this route today, ship the sheet without that line rather than adding an unconfirmed delete.DowngradeAn over-limit account keeps every piece; nothing is auto-deleted, and both downgrade states lead with that sentence. Over-active offers storing down to the limit or a larger plan. Over-total names precisely what is blocked — adding new pieces — and leaves restoring available.No invented dataThere is no stored_at column, so no storage date, month or age is displayed anywhere. No price, limit or count is estimated. Numbers appear only where the real value is known.ImagesPrivate signed URLs only. An expired signature and a genuinely missing image share one identical fallback so the treatment never reveals which occurred. No path, URL or identifier appears in copy, accessibility strings, logs, analytics or errors.Interaction & hapticsOne primary action per state, 56pt filled, 14pt radius, pressed to 0.98 with a shade. Selection haptic on tile select and on chooser rows; success notification only after the restore write returns; nothing decorative and nothing on scroll. The action locks during the write so a double tap cannot restore twice.MotionPlates settle in on a short stagger and the restored piece leaves with a brief fade. Reduce Motion removes the stagger and the travel and keeps every mark, count and announcement — information is never carried by motion alone.AccessibilityFocus order: back → title → capacity line as one node → grid tiles in visual order → active notice → primary action. A tile announces its name, that it is stored, and the action available; the arithmetic is announced once as context, never repeated per tile. Sheets trap focus and pending writes block duplicate submission without trapping. Targets ≥44pt, ≥56pt at AX sizes. Dynamic Type reflows: plates yield height, names wrap in full, two columns hold, nothing clamps.Analytics allowliststorage_view { plan: free | standard | pro }, storage_action { action: select | activate | cancel | retry }, storage_result { outcome: ok | refused_active_full | failed | conflict }, storage_counts { stored, active, total } as integers. Forbidden everywhere: garment name or description, item identifier, image path or URL, price, exact wardrobe contents, free text, and raw server errors.TestsThree-part arithmetic renders from plans.ts for all three plans and omits unknown parts entirely. Active-full refuses restore and disarms; total-full with an active place still permits restore; both-full offers the storing route. Read failure renders its own state, never empty. An empty mutation result is treated as failure with selection and scroll preserved. Double tap yields one write. Cross-device change reconciles without an error. Downgrade states state that nothing is deleted. No stored date appears anywhere. Expired and missing images share one fallback. No analytics payload carries a name, identifier, path or price. 667pt, AX-XXXL, VoiceOver order, Increase Contrast and Reduce Motion all verified.ShippingPresentation-only over existing storage and capacity contracts: no new schema, RPC, grant, package, vendor, permission, data recipient, public surface or native module. Expo fingerprint unchanged; ships over the air on the current binary.
