The New occasion state atlas
Five fields on one page: name, date and time, place, dress code, and a note for the group. One considered form, not a wizard — nothing is hidden behind a Next, and the only required field is the name. The disabled button explains what is missing instead of sitting there grey. Creating lands on the event's detail page.

N-11The form's shape, in one line
NameRequired. 60 characters. The only thing standing between the user and an occasion.
WhenDate, then time. Inside seven days it earns a forecast; beyond it, nothing is printed.
WhereResolved place or free text. Only a resolved one carries coordinates.
Dress codeOne of four, or none. Feeds the same formality scale Packing ranks on.
Note280 characters, shown to everyone invited. The human part Cinch does not read.
Five fields in one scroll, in the order a person says them out loud. A wizard would make the four optional fields feel mandatory by giving each its own screen.
03 · The disabled state
A button that says why
Live — type a name
Name
Create occasion
Give it a name and Cinch can plan it.
The fill and the sentence cross-fade together at the fast duration, so the button becoming available reads as one event. Whitespace does not count as a name — the check is on the trimmed string, which is why a spacebar leaves the button where it was.
Why not greyed out and silent
A dimmed button with no explanation asks the user to audit five fields to find the one that is wrong. The sentence beneath it is the whole fix, and it is written as an invitation rather than a validation error — “Give it a name and Cinch can plan it,” not “Name is required.”
It never turns red, never appears before the user has tried anything, and never moves the button. It is present from the moment the form opens, then leaves — the form's opening line, not its complaint.
