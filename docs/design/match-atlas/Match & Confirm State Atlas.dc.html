Cinch · Match & confirm · build reference
The Match & confirm state atlas
A photographed garment becomes a listing photo. Cinch has already tagged the piece; this flow finds the retailer's own photograph of it, and on confirmation that image becomes how the garment is displayed in the closet. The user's photograph never leaves. Confirming is a promotion, not a replacement — and declining is a fully working outcome.

M-12The flow, in one column
InviteA push row on item detail; one dismissible card in ingest. Never a modal.
WaitThe piece described in the app's own words, over the grid's own shape.
CandidatesA lookbook page. Retailer's photo large, title and source beneath. One selected at a time.
BrandChips above a field. Either one re-runs the search scoped to that brand.
ConfirmListing large, her photograph small and labelled Kept. Oxblood yes, outline Keep my photo.
FailuresFive, each a title, a sentence and a way on. A lookalike always says it is one.
AfterSame tile, same caption, a source colophon. Original one tap away, removable.
One oxblood action per screen and never two. The word “better” appears nowhere in this flow: the offer is a listing photo, not a repair, and the photograph the user took is described as kept, original and hers — never as the thing that was wrong.
