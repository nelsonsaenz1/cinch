### 8.1 The alert, with its falsification

At 00:20:56Z a real customer on build 47 completed The Ten. `paywall_eligible` fired for
placement `ten_completed`. Twenty-nine seconds later she finished the first complete
`arriving → counting → settled → cascade → complete` Reveal a production user has ever
run, and `paywall_eligible` fired again for `reveal_complete`. Both carried
**`eligible: false, reason: "not_free"`**. She saw nothing and backgrounded the app
seven seconds later.

`present-promo.ts` decides this in four lines:

```ts
if (opts.plan !== 'free') { eligible = false; reason = 'not_free'; }
else if (opts.trialing)  { eligible = false; reason = 'trialing'; }
```

**Falsification — the query designed to disprove it.** If she were genuinely a paying or
premium user, `not_free` would be correct and there would be no story. So I asked the
database what plan she is actually on:

```sql
select plan, trial_ends_at from subscriptions s
  join auth.users u on u.id = s.user_id
 where lower(u.email) = 'karencsaenz@yahoo.com';
→  plan = 'free' | trial_ends_at = 2026-09-09
```

**Her plan is `free`. The code said `not_free`.** The only path between those two facts
is the trial fold documented in `use-gate.ts` — *"the fold raises a trialing account to
'pro'"*. The gifted 14-day trial is what silenced the ask. The claim survives.

Second, differently-shaped check — the cohort size, which is the part that makes this
material rather than anecdotal:

```sql
select count(*) from subscriptions s join <real_users> r on r.id = s.user_id
 where s.trial_ends_at > now();
→ 31          -- and 15 of them hold ≥1 garment
```

**31 real users are unaskable.** 22 of those trials expire by Sep 11. P2 already
established that expired-trial users do not come back — 0 of the 7 genuine expirees
returned. So the machine as built is: gift a trial → suppress every ask for the entire
period the user is active → trial expires → user never returns → **never asked at all.**
Eleven trials have already completed that cycle. Twenty-two more do so within ten days.

And the natural experiment that closes it: the *other* woman who used Cinch tonight
signed up at 22:42Z, after A2 shipped. Her `trial_ends_at` is `NULL`. She is the only
real user tonight who **was** shown a paywall. Two users, one night, one build; the only
difference between them is a trial nobody asked for.

*Caveat, stated rather than buried:* her paywall was `add_garment_over_limit`, which
reaches Superwall through `use-gate` rather than `presentPromo`, so it is a supporting
observation and not a controlled arm. The DB-versus-event contradiction above is the
load-bearing evidence.
